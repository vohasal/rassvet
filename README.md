# Рассвет · Telegram Mini App

Локальная демонстрационная версия кофейни «Рассвет» в Ташкенте: клиентское приложение, сервер, база данных и панель сотрудников. Можно показывать в обычном браузере без токенов, сервера и домена. Это не готовый к приёму реальных онлайн-платежей релиз.

## Быстрый запуск

Требуется Node.js 24 или новее.

```sh
npm install
npm run dev
```

- Приложение: http://127.0.0.1:5173
- Панель сотрудников: http://127.0.0.1:5173/admin
- Демо-пароль сотрудников: `rassvet-demo`
- Вход клиента: «Добавить адрес» или «Профиль» → «Войти как тестовый гость».

По умолчанию приложение слушает только этот компьютер. Токены для демонстрации не нужны. `.env` необязателен; для настроек скопируйте `.env.example` в `.env`. Секреты хранятся только на сервере, не в `VITE_*` и не в репозитории. Если системный кеш npm недоступен: `npm install --cache /tmp/rassvet-npm-cache`.

Сборка и запуск без Vite:

```sh
npm run build
npm start
```

После сборки клиент и API доступны вместе на http://127.0.0.1:3001. Страница `/admin` работает по тому же адресу.

## Размещение для показа в Telegram

Обычный импорт этого Vite-проекта в Vercel публикует только `dist/`. Клиент обращается к `/api/catalog` и `/api/me` на том же домене; локальный proxy из `vite.config.ts` работает только при разработке. Без запущенного `server/index.ts` каталог не загрузится. Переменная `VITE_API_URL` в этом проекте не используется.

Для текущей архитектуры нужен один постоянно работающий Node.js-процесс с постоянным диском: Express раздаёт и собранный сайт, и API, SQLite хранит данные, Telegram-бот работает через long polling. Простого переноса `server/index.ts` в Vercel Function недостаточно для базы и фонового опроса бота.

### Render: сайт, API и бот в одном сервисе

В репозитории есть `render.yaml` для **платного** Web Service Starter и постоянного диска 1 ГБ. Перед созданием проверьте итоговую стоимость в Render: [тарифы](https://render.com/pricing), [постоянные диски](https://render.com/docs/disks). Бесплатный сервис без диска может терять SQLite при перезапуске и засыпать — для самостоятельного показа работодателю этот вариант ненадёжен.

1. Отправьте изменения проекта, включая `render.yaml`, в GitHub.
2. Войдите в [Render](https://dashboard.render.com/) через GitHub → **New → Blueprint**, выберите репозиторий `vohasal/rassvet` и ветку с изменениями.
3. Введите `TELEGRAM_BOT_TOKEN` того бота, из которого открываете Mini App. Скопируйте значение из локального `.env` в секретные переменные Render. Не добавляйте `.env` в GitHub. `ADMIN_PASSWORD` Blueprint сгенерирует автоматически; его можно посмотреть в разделе **Environment** сервиса.
4. Проверьте платный тариф и диск, затем создайте сервис. Дождитесь успешного деплоя. Render установит Node.js 24, выполнит сборку и запустит `npm start` на `0.0.0.0`.
5. Откройте выданный адрес `https://<имя-сервиса>.onrender.com/api/health`: ожидается `{"ok":true}`. По `/api/catalog` должен возвращаться JSON с товарами, по `/` — меню, по `/admin` — панель сотрудников.
6. В BotFather у этого же бота замените адрес **Main Mini App** и **Menu Button** на новый HTTPS-адрес Render. `MINI_APP_URL` на Render можно не задавать: сервер использует предоставленный хостингом `RENDER_EXTERNAL_URL`. Если подключите свой домен, задайте его явно в `MINI_APP_URL`.
7. Остановите локальную копию сервера с тем же токеном: одновременно должен работать только один процесс long polling. Если бот раньше использовал webhook, его нужно отключить перед запуском polling.
8. Полностью закройте Mini App, отправьте боту `/start` и откройте новую кнопку. Старые кнопки в переписке сохраняют старый URL. Поделитесь собственным номером `+998`, оформите тестовый заказ и проверьте его в `/admin`.

В Render оставьте `DEMO_MODE=true`: это сохраняет тестовую оплату без списания денег. `STAFF_CHAT_ID` и `YANDEX_MAPS_API_KEY` можно добавить позже в **Environment**; для просмотра меню они не нужны. Если используете ключ карт с ограничением по домену, добавьте адрес Render в разрешённые домены.

Данные будут храниться в `/var/data/rassvet.sqlite`. Этот каталог должен оставаться на постоянном диске; запускайте ровно один экземпляр приложения. При первом размещении создаётся новая база с исходным меню — локальные заказы сами не переносятся. `/api/health` проверяет HTTP-сервер и доступность базы, но не соединение с Telegram; его проверяйте через `/start` и логи сервиса.

Адрес Vercel можно пока оставить, но в BotFather укажите рабочий адрес Render. Если понадобится сохранить Vercel как основной домен, потребуется отдельно настроить проксирование `/api` к запущенному серверу.

### Другой Node.js-хостинг или VPS

Используйте Node.js 24 и один процесс приложения:

```sh
npm ci --include=dev
npm run build
npm start
```

Настройте `NODE_ENV=production`, `HOST=0.0.0.0`, порт хостинга в `PORT`, `DATABASE_PATH` на постоянном диске, `DEMO_MODE=true`, уникальный `ADMIN_PASSWORD`, `TELEGRAM_BOT_TOKEN` и публичный HTTPS-адрес в `MINI_APP_URL`. В production сервер откажется стартовать с отсутствующим / стандартным паролем сотрудников или без собранного фронтенда. Хостинг должен завершать HTTPS и передавать запросы приложению; для VPS также настройте автозапуск процесса и HTTPS reverse proxy.

## Сценарий показа на 5 минут

1. Откройте приложение, посмотрите категории и фотографии меню. Поиск фильтрует названия на выбранном языке.
2. Нажмите «Добавить адрес», войдите как тестовый гость. Ещё раз откройте адреса и нажмите «Подставить тестовый адрес рядом с кофейней». Укажите квартиру, подъезд и комментарий, сохраните.
3. Добавьте капучино, выберите молоко, добавьте булочку. В корзине проверьте увеличение, уменьшение и удаление позиций. Есть подтверждение полного очищения.
4. Оформите доставку, введите имя и контактный номер. Примените `RASSVET10` (демо-скидка 10%). Выберите Click или Payme.
5. На экране «Тестовая оплата» выберите «Отказ банка», затем повторите оплату и выберите успех. Деньги не списываются. Заказ сохраняется между попытками и не дублируется.
6. В соседней вкладке откройте панель сотрудников. Откройте заказ, проверьте адрес, координаты, квартиру, молоко, телефон, комментарий, скидку и итог.
7. Меняйте статусы: принят → готовится → готов к выдаче → в пути → получен. Клиентская страница обновляется примерно раз в 5 секунд, пока вкладка активна. Для самовывоза этап «в пути» отсутствует.
8. В разделе «Меню» отключите товар, затем вернитесь к каталогу. Он станет недоступен; сервер также запретит заказать уже добавленный недоступный товар. После показа включите товар обратно.
9. Откройте профиль: смените язык на English / O‘zbekcha, тему, загрузите аватар. Перезагрузите страницу — настройки сохранятся.

## Что реализовано

- React + TypeScript + Vite, адаптивный интерфейс для телефона и компьютера, светлая / тёмная / системная тема.
- Русский, английский, узбекский на латинице: интерфейс, названия товаров, акции и статусы.
- 24 стартовые позиции в 6 категориях, локальные фотографии, поиск, варианты молока, стоп-лист.
- Акции и события с редактированием на трёх языках; управление промокодами.
- Корзина с вариантами товара, количеством, удалением и очисткой. Корзина сохраняется в браузере.
- Серверные профили, адреса, аватары, история заказов, временные метки статусов.
- Наличные; локальный симулятор Click / Payme: успех, отказ, уход без оплаты, повторная попытка, тестовый возврат при отмене сотрудником.
- Защита от повторного оформления через ключ идемпотентности. Цены, скидка, варианты, минимальная сумма, стоп-лист и зона проверяются на сервере. Клиент не задаёт итоговую сумму.
- Панель сотрудников с отдельной HttpOnly-сессией, пароль, ограничения попыток входа; произвольный переход статусов запрещён, неоплаченный заказ нельзя готовить.
- Telegram: проверка подписанного `initData` и его срока, запрос контакта, проверка `contact.user_id === message.from.id`, привязка номера к пользователю. Бот использует long polling.
- Очередь Telegram-уведомлений сотрудникам о принятых заказах и клиентам об изменениях статуса, с повторными попытками при ошибках. Работает только с настроенным ботом и адресатом.
- Яндекс Карты: загрузка JS API по ключу, поиск адреса, выбор точки, обратное геокодирование и круг доставки. Без ключа — честный ручной режим, ссылка на Яндекс Карты, геолокация браузера и тестовый адрес.

## Правила кофейни

- Адрес: Чимкент, 17. Центр доставки: `41.305414, 69.272900`.
- Радиус 5 км по прямой от кофейни, не дорожный пробег курьера.
- Минимум 50 000 сум **до скидки**, без стоимости доставки; в этой версии одинаков для доставки и самовывоза.
- Приём заказов 12:00–20:00, часовой пояс `Asia/Tashkent`; в 20:00 приём закрыт.
- В демонстрации по умолчанию включён приём вне расписания. В панели → «Настройки» можно выключить его и проверить реальные часы. При `DEMO_MODE=false` обход не действует.
- Доставка: **условные 15 000 сум**, настраивается в панели. Это не котировка Яндекса. Курьера сотрудник пока вызывает вручную. Примечание по доставке отображается клиенту.
- Альтернативное молоко: условные +10 000 сум, объёмы и доступность вариантов требуют подтверждения кофейней.
- `RASSVET10`, акция знакомства и анонс встречи — демонстрационные материалы. Анонс не заявляет реальное запланированное мероприятие.

## Подключения и границы демонстрации

| Сервис | Что уже есть | Что требуется дальше |
| --- | --- | --- |
| Telegram | Валидация подписи, контакт, бот, сессии, уведомления | `TELEGRAM_BOT_TOKEN`, HTTPS-адрес в `MINI_APP_URL`, настройка Mini App в BotFather; для сотрудников `STAFF_CHAT_ID` |
| Яндекс Карты | Поиск, точка, геокодирование, проверка зоны | `YANDEX_MAPS_API_KEY` с доступом к JS API 2.1 и геокодеру, ограничения ключа по домену; ручная проверка с настоящим ключом |
| Click | Полный локальный демонстрационный сценарий | Интернет-мерчант, тестовые реквизиты, реализация подписанных callback-методов Click и проверка в провайдерской песочнице |
| Payme | Полный локальный демонстрационный сценарий | Интернет-мерчант, тестовые реквизиты, реализация Merchant API и проверка в провайдерской песочнице |
| Яндекс Доставка | Адрес и координаты для сотрудника, ручные статусы | Договор / доступ к API в Узбекистане, тариф, создание заявки, события курьера |

**Локальный симулятор оплаты не является песочницей Click или Payme.** Успешный результат выбирается пользователем только в явно помеченном демо-режиме. Настоящие платёжные callback-обработчики пока не реализованы, боевые онлайн-платежи заблокированы. Наличие терминала в кофейне не означает наличие API интернет-мерчанта. Не вводите номера карт — интерфейс их не запрашивает.

Для подключения Telegram:

1. Создайте бота через BotFather и добавьте токен в `.env`.
2. Когда появится HTTPS-адрес, укажите его в `MINI_APP_URL`, настройте Main Mini App / кнопку меню в BotFather.
3. Откройте `/start` в боте и поделитесь своим контактом. Либо поделитесь номером внутри Mini App.
4. Для уведомлений сотрудникам добавьте бота в рабочую группу и укажите её `STAFF_CHAT_ID`.
5. Перезапустите приложение. Не запускайте одновременно несколько копий long polling для одного токена. Если раньше использовался webhook, отключите его перед long polling.

Запрос контакта / провайдерские карты / уведомления в реальном Telegram не проверены без ключей. Валидация подписи и ограничения авторизации покрыты автоматическими тестами. Поддерживаются контактные номера Узбекистана `+998`.

## Данные и архитектура

Для демонстрации используется встроенная **SQLite** в Node.js 24: установка отдельной СУБД не нужна. Это осознанное упрощение относительно предложенного PostgreSQL для размещения. Профили, заказы, настройки, стоп-лист, сессии и очередь уведомлений хранятся в `data/rassvet.sqlite`, сохраняются после перезапуска. Для многосерверного размещения потребуется миграция в PostgreSQL и отдельное хранение аватаров.

- `server/app.ts` — API, авторизация, расчёт заказов, панель, очередь уведомлений.
- `server/domain.ts` — подпись Telegram, время Ташкента, расстояние.
- `server/db.ts` — схема и первоначальное заполнение.
- `server/telegram.ts` — контакт и отправка уведомлений.
- `server/menu.json` — стартовые данные каталога, ссылки на источники изображений.
- `src/App.tsx`, `src/Orders.tsx`, `src/Profile.tsx`, `src/Admin.tsx` — клиентские экраны.
- `src/i18n.ts` — переводы и сообщения ошибок.
- `src/styles.css` — дизайн и адаптивность.

Меню заполняется один раз; повторный запуск не стирает правки сотрудников. Изменение `menu.json` не перезаписывает существующие записи. Рабочая база не используется автотестами. Для резервного копирования остановите приложение и скопируйте каталог `data/` целиком. Не публикуйте его: там контактные данные и сессии.

Перед реальными заказами нужно согласовать составы / аллергены, объёмы, стоимость молока, тариф и зону доставки, условия скидок, согласие на обработку данных и правила возвратов, получить оригинал логотипа, подключить мерчантов и курьера, настроить HTTPS, новый пароль сотрудников, резервное копирование и мониторинг. Удалять интеграционные ограничения переключением `DEMO_MODE` нельзя.

## Проверки

```sh
npm test
npm run build
npm run test:e2e
```

Браузерные проверки используют установленный Google Chrome. Изолированные тестовые серверы занимают порты 5174 / 3002, база хранится в `test-results/`. Проверяются пользовательский путь на 1440 px и 390 px, оплата с отказом и повтором, получение сотрудником, доставка, языки, тема, стоп-лист и очистка корзины. API-тесты проверяют авторизацию, чужие заказы, расчёт суммы, идемпотентность, неверные промокоды, зону доставки, переходы статусов, отмену и подпись Telegram.
